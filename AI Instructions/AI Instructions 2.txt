--------------------------------------------------------------------------------
 3. ROOT CAUSE ANALYSIS: WHY BULK PIPES (0x82 / 0x86) ARE AWAITING STROBE
--------------------------------------------------------------------------------
In the ST-133 hardware architecture:
1. The Cypress FX2 USB controller operates Endpoints 0x08, 0x82, and 0x86 in Slave FIFO Hardware Mode.
2. In Slave FIFO mode, USB data packets cannot move through the FIFO buffers unless the internal FPGA and the detector head digitizer clock drive the FIFO strobe pins (SLRD, SLWR, FLAGA).
3. The InGaAs photodiode array saturates rapidly unless placed in a continuous background charge-flushing cycle (PICM_Start_controller).
4. Because the FPGA command sequence on Pipe 0x08 has not yet latched the continuous clear / digitizer clock, the FIFO strobe remains in a hardware wait state, causing bulk reads on 0x82 and writes on 0x08 to time out with ERROR_SEM_TIMEOUT (err=121).

1. Implement Continuous Background Charge-Clear Cycle (PICM_Start_controller):
   - In PIXCM32.dll (FUN_1001089c / FUN_10010d2b / 0x4D8), implement the background photodiode flush loop that runs continuously between acquisitions.
   - This keeps the InGaAs diodes from saturating and keeps the FPGA digitizer clock actively strobing the FIFO.

2. Format 7-Byte / 8-Byte PIPP Command Packets on Pipe 0x08:
   - Decompiled from Pipp32.dll (L9780 - L9830):
     * Byte 0: Command ID (0x40 = Download EPLD microcode, 0x01 = Trigger, 0x32 = Start Clear, 0x30 = Stop Clear).
     * Bytes 1..2: Physical EPLD Address (0x4000 / 0x8000).
     * Byte 3: Payload Length.
     * Bytes 4..n: Microcode timing bytes (0xE0 = Reset, 0x20 = Flush, 0x40 = Gate Time, 0x00 = Clock 512 Pixels, 0xBD = End).

3. Extract Cold-Finger RTD Cryogenic Temperature from Digitized Stream:

     * Words 2..513: 512 linear 16-bit InGaAs pixel channels.
   - Update get_temperature() in st133_usb.py to parse Word 1 directly from the active digitized frame.
