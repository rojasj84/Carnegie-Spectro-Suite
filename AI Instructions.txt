 3. ROOT CAUSE ANALYSIS & GHIDRA REVERSE-ENGINEERING FINDINGS
--------------------------------------------------------------------------------
On 32-bit Windows XP, Princeton Instruments WinSpec operated using:
  - APAUSB.SYS (legacy 32-bit WDM kernel driver based on ezusb.sys)
  - PIDC32.dll / PIXCM32.dll / contrman.dll / Pipp32.dll

Why these legacy 32-bit DLLs fail on modern 64-bit Windows:
1. Hardcoded Driver Object Dependency:
   - Inside pidc32.dll, _PIDC_Create_datacollect_object strictly calls CreateFileA("\\\\.\\APAUSB0").
   - On 64-bit Windows, APAUSB.SYS cannot load (it lacks 64-bit digital signatures and uses 32-bit kernel pointers).
   - Modern 64-bit Windows loads piusbwdf.sys instead, which exposes PnP Device Interface GUIDs rather than the legacy \\.\APAUSB0 DOS device symlink.
2. Raw Kernel DMA Memory Offsets:
   - Inside PIXCM32.dll, frame readout dereferences a 32-bit contiguous DMA circular ring buffer at struct offset 0x10FC.
   - Because piusbwdf.sys handles transfers asynchronously via KMDF request queues, calling these 32-bit functions causes memory access violations.

Why Direct 64-Bit Bulk Reads Required Timing Microcode:
- While 8051 SRAM microcode (PI133B.DAT) loads successfully, the internal EPLD timing generator requires a microcode opcode sequence (decompiled from PIXCM32.dll FUN_1002c88f / FUN_1002cf00) to clock charge from the InGaAs array through the 16-bit ADC into the USB bulk FIFO buffer.

 4. EXACT REVERSE-ENGINEERED PROTOCOL SPECIFICATIONS (GHIDRA DECOMPILED)
--------------------------------------------------------------------------------
The following constants, structs, and calling conventions were proven via Ghidra 12.1.2:

A. Cypress EZ-USB FX2 Reset Control:
   - Register: 0xE600 (CPUCS register in external RAM)
   - Assert Reset:   Vendor Request 0xA0, Address 0xE600, Data = [0x01]
   - Release Reset:  Vendor Request 0xA0, Address 0xE600, Data = [0x00]

B. Exact 10-Byte USB Setup Packet (USBDRVD.DLL at 0x10001A80):
   struct USB_SETUP_PACKET {
       uint8  direction;     // 0 = OUT, 1 = IN
       uint8  bRequestType;  // 2 = Vendor
       uint8  bRecipient;    // 0 = Device
       uint8  reserved1;     // 0
       uint8  bRequest;      // 0xA0 (Firmware), 0x8D (EPLD Config), 0x01 (Trigger), 0x8B (Temp)
       uint8  reserved2;     // 0
       uint16 wValue;        // Register address / Exposure param
       uint16 wIndex;        // Pipe index (0)
   }; // Total = exactly 10 bytes

C. 64-Bit Driver IOCTLs (piusbwdf.sys & USBDRVD.DLL):
   - IOCTL_EZUSB_VENDOR_REQUEST = 0x00220425 (Legacy alias: 0x00222010)
   - IOCTL_EZUSB_BULK_READ      = 0x00220429 (Legacy alias: 0x00222048)
   - IOCTL_EZUSB_BULK_WRITE     = 0x0022042E
   - IOCTL_EZUSB_RESET_PIPE     = 0x0022040C

D. InGaAs Hardware Timing Opcode Stream (PIXCM32.dll FUN_1002c88f / FUN_1002cf00):
   - Opcode 0xE0 / 0x20: Pre-exposure photodiode charge flush
   - Opcode 0x44: Hardware loop repeat start
   - Opcode 0x40: Integration gate duration (scaled to 153 us quantum from omavb.dat)
   - Opcode 0x46 / 0xBD: Loop repeat end and arming completion
   - Opcode 0x00: ADC sample clocking for 512 linear channels

E. 10-Field Hardware Experiment Block (PIXCM32.dll 0x28F80):
   struct.pack('<IIHHHHHHH',
       exp_time_ms,   # uint32: Exposure duration (e.g. 100)
       frames_count,  # uint32: Accumulation count (e.g. 1)
       x_dimension,   # uint16: Number of active pixels (512)
       y_dimension,   # uint16: Sensor height (1)
       gain_index,    # uint16: Pre-amp gain (3 = High Sensitivity)
       speed_index,   # uint16: Readout clock (1 = 1 MHz)
       shutter_mode,  # uint16: 0 = Normal / Open
       trigger_mode,  # uint16: 0 = Internal Free Run
       clean_cycles   # uint16: 1 = Pre-exposure flush
   )

F. RTD Temperature Query (PIXCM32.dll & contrman.dll):
   - Vendor Request 0x8B (IN transfer, 4 bytes):
     * raw_adc = struct.unpack('<h', resp[:2])[0]
     * temperature_c = raw_adc / 10.0 (typically -97.5 °C to -100.0 °C under LN2 cooling).
