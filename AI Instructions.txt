 3. ROOT CAUSE ANALYSIS: THE 64-BIT USB COMMUNICATION BARRIER
--------------------------------------------------------------------------------
On 32-bit Windows XP, Princeton Instruments WinSpec operated using:
  - APAUSB.SYS (legacy 32-bit WDM kernel driver based on ezusb.sys)
  - PIDC32.dll / PIXCM32.dll / contrman.dll / Pipp32.dll

Why these legacy 32-bit DLLs fail on modern 64-bit Windows:
1. Hardcoded Driver Object Dependency:
   - Inside pidc32.dll, _PIDC_Create_datacollect_object strictly calls CreateFileA("\\\\.\\APAUSB0").
   - On 64-bit Windows, APAUSB.SYS cannot load (it lacks 64-bit digital signatures and uses 32-bit kernel pointers).
   - Modern 64-bit Windows loads piusbwdf.sys instead, which exposes PnP Device Interface GUIDs rather than the legacy \\.\APAUSB0 DOS device symlink.
2. Raw Kernel DMA Memory Offsets:
   - Inside PIXCM32.dll, frame readout dereferences a 32-bit contiguous DMA circular ring buffer at struct offset 0x10FC.
   - Because piusbwdf.sys handles transfers asynchronously via KMDF request queues, calling these 32-bit functions causes memory access violations (e.g. access violation reading 0x000010FC).

Why Direct 64-Bit Bulk Reads Currently Return 0 Bytes:
- Direct 64-bit USB control transfers (IOCTL_EZUSB_VENDOR_REQUEST 0x00222010) and bulk reads (IOCTL_EZUSB_BULK_READ 0x00222048) work without errors.
- We successfully inject the 8051 microcode (PI133B.DAT) and the InGaAs timing patch (omavb.dat) into volatile SRAM.
- However, the ST-133's internal FPGA/EPLD timing generator requires a specific hardware gate-arming handshake sequence to clock charges from the InGaAs array through the 16-bit A/D converter into the USB bulk FIFO buffer.

 4. EXACT REVERSE-ENGINEERED PROTOCOL SPECIFICATIONS
--------------------------------------------------------------------------------
The following constants, structs, and calling conventions were proven:

A. Cypress EZ-USB FX2 Reset Control:
   - Register: 0xE600 (CPUCS register in external RAM)
   - Assert Reset:   Vendor Request 0xA0, Address 0xE600, Data = [0x01]
   - Release Reset:  Vendor Request 0xA0, Address 0xE600, Data = [0x00]

B. Firmware & Timing Files:
   - Base 8051 Kernel: PI133B.DAT (13,058 / 13,062 bytes, 403-416 BIX records)
     * Format: [Length (1 byte), Addr_MSB (1 byte), Addr_LSB (1 byte), Data (Length bytes)]
   - InGaAs Timing Table: omavb.dat (250 bytes, 125 uint16 words)
     * Header: 0xFFFF, cycle frequency 0x99 (153 us), gate integration phases.

C. 64-Bit Driver IOCTLs (piusbwdf.sys):
   - IOCTL_EZUSB_VENDOR_REQUEST = 0x00222010
   - IOCTL_EZUSB_BULK_READ      = 0x00222048
   - IOCTL_EZUSB_BULK_WRITE     = 0x0022204C

D. 9-Parameter stdcall Calling Convention (USBDRVD.DLL):
   USBDRVD_VendorOrClassRequestOut(
       hDev, bDirection (0=OUT), bRequestType (2=Vendor), bRecipient (0=Device),
       bRequest, wValue, wIndex, pBuffer, dwLength
   )

E. 10-Field Hardware Experiment Block (PIXCM32.dll 0x28F80):
   struct.pack('<IIHHHHHHH',
       exp_time_ms,   # uint32: Exposure duration (e.g. 100)
       frames_count,  # uint32: Accumulation count (e.g. 1)
       x_dimension,   # uint16: Number of active pixels (512)
       y_dimension,   # uint16: Sensor height (1)
       gain_index,    # uint16: Pre-amp gain (3 = High Sensitivity)
       speed_index,   # uint16: Readout clock (1 = 1 MHz)
       shutter_mode,  # uint16: 0 = Normal / Open
       trigger_mode,  # uint16: 0 = Internal Free Run
       clean_cycles   # uint16: 1 = Pre-exposure flush
   )

F. WinX32 COM / ActiveX Automation Architecture (from WinX32_Automation_3X_for_Visual_Basic.pdf):
   In Visual Basic 6 (VB6), external applications automate WinSpec using its embedded COM Type Library (WINX32Lib):
   - Objects Used:
     * ExpSetup (ProgID "WinX32.ExpSetup"): Manages exposure parameters and triggers acquisition.
     * DocFile (ProgID "WinX32.DocFile"): Receives the acquired frame buffer and saves SPE files.
     * WinX32App (ProgID "WinX32.Winx32App"): Main application controller.
   - Core Acquisition Pattern:
     Dim objExp As New ExpSetup
     Dim objDoc As New DocFile
     objExp.SetParam EXP_EXPOSURE, 0.1  ' Set exposure in seconds
     objExp.SetParam EXP_ACCUMS, 1      ' Set accumulation count
     If objExp.Start(objDoc) Then       ' Triggers hardware acquisition
       While objExp.GetParam(EXP_RUNNING, intStatus) And intStatus = 0
         DoEvents                       ' Wait for frame completion
       Wend
       Dim vntFrame As Variant
       objDoc.GetFrame 1, vntFrame      ' Retrieves 512 raw counts
     End If

 5. RECOMMENDED STRATEGIES TO ACHIEVE 64-BIT READOUT
--------------------------------------------------------------------------------
To complete the 64-bit driver and receive digitized physical counts (>2000 counts from the active light source), use one of the following approaches:

APPROACH 1: USB Packet Capture & Replay (Highest Confidence & Fastest)
1. On the working 32-bit Windows XP PC, install Wireshark + USBPcap (or Sysinternals / USBTrace).
2. Start capture, take a 0.1s single-frame acquisition in WinSpec, and stop capture.
3. Inspect the .pcap / .pcapng trace:
   - Identify the exact sequence of Control Transfers (bRequest, wValue, wIndex, Data) sent to EP0 right before acquisition.
   - Replay those exact packets in spectro_suite/hardware/detectors/st133_usb.py.
   - The FPGA will immediately begin clocking samples into Bulk Pipe 0.

APPROACH 2: Reconstructing the Pre-Charge Gate Arming in PIXCM32.dll
1. Inspect PIXCM32.dll function at offset 0x27C10 -> sub_28B33 -> 0x28F80 -> 0x29160.
2. Isolate the 4-byte payload written to the EPLD register bank (Vendor Request 0x8D) that releases the pre-charge integrate gate prior to asserting Trigger (0x01).

APPROACH 3: Network Acquisition Bridge (Instant Production Solution)
1. Run remote_ingaas_bridge_for_32bit_pc.py on the 32-bit Windows XP PC where WinSpec and APAUSB.SYS run natively.
2. The script listens on TCP port 5000 and streams 512 raw counts over the local network / Ethernet crossover cable.
3. SpectroSuite on this 64-bit PC receives the live stream, controls the Horiba HR460 on COM1, and performs real-time calibration and ruby pressure fitting.
